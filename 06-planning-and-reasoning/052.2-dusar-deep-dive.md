# DuSAR 双策略框架深度解析

> 本文是 [052-plan-and-solve-replanning.md](./052-plan-and-solve-replanning.md) 第十节的补充阅读。

---

## DuSAR 是什么？

**DuSAR** = **Du**al-**S**trategy **A**daptive **R**easoning，核心思想是让 Agent 同时拥有"**宏观规划能力**"和"**微观经验学习能力**"，两条腿走路。

---

## 两条腿：两个策略同时工作

```
DuSAR
 ├── 策略 1：子目标导向（全局规划）→ 负责"拆任务"
 └── 策略 2：经验驱动  （局部适应）→ 负责"怎么做好每个子任务"
```

### 策略 1：子目标导向（自上而下拆任务）

面对一个复杂任务，先把大目标拆成若干**子目标**，每个子目标相对独立：

```
任务：写一篇完整的市场分析报告
    ├── 子目标 1：收集行业数据
    ├── 子目标 2：分析竞争对手
    ├── 子目标 3：整理趋势洞察
    └── 子目标 4：生成结论和建议
```

> 这部分和 Plan-and-Execute 很像，区别在于 DuSAR 的子目标**是动态可调整的**，不是写完就固定。

---

### 策略 2：经验驱动（从历史中学习"怎么做"）

对于每个子目标，不是从零开始思考怎么做，而是**先从经验库里找**有没有类似任务的解决策略：

```
子目标：分析竞争对手
    ↓
查经验库：上次做竞品分析用了什么策略？效果如何？
    ↓
找到了 → 复用并优化上次策略
没找到 → 探索新策略，做完后记录到经验库
```

经验库（`experience_bank`）就像一个**不断积累的记忆本**：
- 每次完成一个子目标 → 把"子目标类型 + 用了什么策略 + 结果如何"记录下来
- 下次遇到类似子目标 → 直接查库，不用重复思考

---

## 两个关键动态机制

### 动态机制 1：根据结果重新拆解子目标

```
完成子目标 2（分析竞争对手）
    ↓
发现：市场格局发生了重大变化，原来的子目标 3/4 方向不对
    ↓
redecompose()：重新拆解剩余子目标
    ├── 原子目标 3：整理趋势洞察 → 改为：重新定义趋势评估维度
    └── 原子目标 4：生成结论     → 改为：加入风险预警建议
```

> 这就是"长时域任务"特别需要的能力——**边做边修正路线图**，不是死板地执行原始计划。

### 动态机制 2：经验库自我更新

```
完成子目标 → experience_bank.record(subgoal, result)
                         ↓
           记录：子目标类型 + 策略 + 结果
           ↓
           下次同类子目标 → 直接查库获取最佳策略
```

> Agent 越做越聪明，**经验库让规划能力随时间增长**。

## 完整流程图

```
复杂任务
  │
  ▼
策略 1：拆解为子目标列表 [S1, S2, S3, S4]
  │
  ▼
循环处理每个子目标 Si：
  │
  ├── 策略 2：查经验库 → 有匹配？
  │       ├── 有 → 复用历史最佳策略执行
  │       └── 无 → 探索新策略执行
  │
  ├── 结果检查：是否改变了后续上下文？
  │       ├── 是 → redecompose()：重新拆解剩余子目标
  │       └── 否 → 继续下一个子目标
  │
  └── 更新经验库：record(Si, result)
  │
  ▼
所有子目标完成 → 输出最终结果
```

## 与 ALAS 的对比

| 维度 | DuSAR | ALAS |
|---|---|---|
| **核心关注** | 怎么规划 + 怎么越做越好 | 怎么保证每步不出错 |
| **解决的问题** | 长时域任务的规划适应性 | 单步失败的状态污染 |
| **关键机制** | 经验库 + 动态重新拆解 | 快照 + 回滚 + 重试 |
| **类比** | 一个有经验的项目经理 | 一个有撤销键的编辑器 |
| **互补关系** | 管"规划层面"，可结合 ALAS 使用 | 管"执行层面"，可结合 DuSAR 使用 |

---

## 一句话总结

DuSAR 让 Agent 既有**全局视野**（拆子目标），又有**局部智慧**（经验复用），还能**边走边调整**（动态重拆解），特别适合需要长时间执行、且中途情况会变化的复杂任务。
